Option 1 — Recommended

The goku CLI — macOS, Linux and Windows

The CLI installs natively on each platform and runs Goku in Docker for you — no docker commands to write. It installs the goku command, plus mimir, its former name, as a deprecated alias (details).

macOS and Linux

terminal
$ curl -fsSL https://tanuj24.github.io/goku/install.sh | sh

Windows (PowerShell)

PowerShell
PS> irm https://tanuj24.github.io/goku/install.ps1 | iex

Start your local cloud

terminal
$ goku start

goku start downloads the image on first run, starts Goku and opens the web console at http://localhost:8080. Your AWS CLI, SDKs and apps talk to http://localhost:4566 — point them at it with one command.

CommandWhat it does
goku startDownloads the image on first run, starts Goku and opens the console.
goku statusShows what's running — also for a Goku started another way.
goku stopStops Goku. Everything is saved in your data folder.
goku logs -fFollows the container logs.
goku updateUpgrades to the newest version. Your resources are preserved.
goku update --cliUpdates the goku command itself, verified against its published checksums.
goku dataShows where your data lives and how big it is; goku data open opens the folder, goku data migrate moves an older install's volume into it.
goku openOpens the console, or a page in it: goku open sqs, goku open lambda my-fn.
goku envPrints the endpoint and credential variables for your AWS CLI and SDKs.
goku doctorChecks Docker, ports, saved state, curl and the backend's features, whether the MCP endpoint answers and whether your AWS profiles are mounted.
goku mcpGoku's MCP server for AI assistants, on stdin and stdout. Starts Goku when it isn't running.
goku mcp configPrints the setup for Claude Code, Claude Desktop, Cursor, VS Code and Windsurf; goku mcp config cursor prints one.
goku ws lsLists your workspaces with their state, services and memory, and what runs outside them. goku ws is short for goku workspace.
goku ws create NAMESaves services as a workspace: --services lambda,ecs,dynamodb, --template data or --from-current; --auto-pause 30 pauses it after 30 idle minutes.
goku ws start NAMETurns a workspace's services on and brings back what it paused or stopped. pause freezes its containers, resume unfreezes them, stop frees their memory and keeps the data, and switch starts it and stops the others.
goku ws export NAMEWrites a workspace as JSON to share; goku ws import FILE adds it. Also show, edit, delete and stop-outside.
goku iam profilesLists the AWS profiles on this machine: type, region, SSO account and role, never keys.
goku iam connectConnects the IAM Lab to the AWS account of a profile (--profile NAME) and scans its IAM, read-only. Signs in on your machine, SSO and MFA included.
goku iam rolesLists the account's roles: who each one trusts, when it was last used and its policies. goku iam roles deploy searches.
goku iam access ROLEWhat a role can do: who can assume it, its policies, the actions it is allowed per service and its risks. Guide.
goku uninstallRemoves Goku and keeps your data folder; add --purge to delete it too.

The CLI also drives a running Goku: goku services, goku ready, goku snapshot, goku chaos, goku iam and goku lambda debug. Run goku help <command> for the details. The goku ws and goku iam role commands need Goku 4.2 and goku CLI 0.6.0 or later.

Connect your tools

Point your AWS CLI and SDKs at Goku

goku env sets AWS_ENDPOINT_URL, AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY (test / test) and AWS_REGION, so the AWS CLI v2 and every AWS SDK talk to Goku with no code changes.

macOS and Linux

terminal
$ eval "$(goku env)"

Windows (PowerShell)

PowerShell
PS> goku env --shell powershell | Invoke-Expression

Then aws s3 ls lists your local buckets. On macOS and Linux, eval "$(goku env --unset)" switches back to real AWS. To configure a tool by hand, use the endpoint http://localhost:4566, region us-east-1 and any local credentials such as test / test.

Next, create your first bucket, table, queue and function with the run AWS locally guide.

Connect an AI assistant

Goku serves an MCP server at http://localhost:8080/mcp, so AI assistants can work with your local AWS too, and nothing they change reaches real AWS. For Claude Code:

terminal
$ claude mcp add goku -- goku mcp

goku mcp starts Goku if it isn't running, and goku mcp config prints the setup for Claude Desktop, Cursor, VS Code and Windsurf. The MCP guide covers every client and the 34 tools.

Use your AWS profiles in the IAM Lab

The IAM Lab can show what the roles of your real AWS account can do, with an AWS profile you already have. goku start mounts your AWS config folder read-only into Goku (~/.aws, or %USERPROFILE%\.aws on Windows, at /run/goku/aws). Only the IAM Lab reads it, every AWS call it makes is read-only, and credentials are held in memory only. goku update adds the mount to an existing container, goku doctor shows whether it is there, and GOKU_AWS_PROFILES=off leaves it out.

Running the image with plain Docker? Add -v ~/.aws:/run/goku/aws:ro to your docker run (on Windows, -v "$env:USERPROFILE\.aws:/run/goku/aws:ro"). Profiles that need your terminal, such as an MFA code or an expired SSO sign-in, connect with goku iam connect --profile NAME. The role permissions guide walks through it.

Option 2

Docker without the CLI

Already have Docker? Run the image directly — it's the same image the CLI runs.

macOS and Linux (bash)

terminal
$ mkdir -p ~/.goku/data
docker run -d --name goku \
  -p 8080:80 -p 4566:4566 -p 5500-5524:5500-5524 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v ~/.goku/data:/app/data \
  -v /tmp/goku-glue:/tmp/goku-glue \
  tanujsoni027/goku:latest

Windows (PowerShell)

PowerShell
PS> New-Item -ItemType Directory -Force "$env:LOCALAPPDATA\Goku\data" | Out-Null
docker run -d --name goku `
  -p 8080:80 -p 4566:4566 -p 5500-5524:5500-5524 `
  -v /var/run/docker.sock:/var/run/docker.sock `
  -v "$env:LOCALAPPDATA\Goku\data:/app/data" `
  -v /tmp/goku-glue:/tmp/goku-glue `
  tanujsoni027/goku:latest

The web console is at http://localhost:8080 and the AWS-compatible endpoint at http://localhost:4566. Add -e GOKU_SERVICES=all to start with every service subscribed, -p 2000:2000/udp to send X-Ray segments from apps on your host, and -v ~/.aws:/run/goku/aws:ro to use your AWS profiles in the IAM Lab.

Everything lives in your data folder. Goku keeps every bucket, table, function and job in the folder you mount at /app/data, and the data of its engines too: RDS PostgreSQL databases, OpenSearch, ECR, DocumentDB, MemoryDB, Amazon MQ and Redshift, plus MSK on Linux. Stop Goku, update it or reset Docker, then start it with the same folder and you resume where you left off. Leave the -v for the folder out and Goku keeps its state in a goku-data Docker volume instead. On macOS and Windows, RDS MySQL and MariaDB data and MSK (Kafka) data stay in Docker volumes, since those engines can't run on a Docker Desktop file share.
Before you start

Requirements

Docker Docker Desktop on macOS and Windows; Docker Engine or Docker Desktop on Linux. Lambda, EC2, ECS, RDS, Glue and friends run as sibling containers, so Goku needs access to the Docker socket.
Any modern machine The image is multi-arch (linux/amd64 + linux/arm64), so it runs natively on Apple Silicon, Intel and AMD machines and Linux CI.
No AWS account, ever Once the image and any runtime images your services need are pulled, everything runs on your machine. The first Glue or Spark run pulls a large runtime image — give it a minute.
Coming from Mimir

Upgrading an existing install

Everything you created carries over. The easiest way is the CLI: install it (the commands above), then run

terminal
$ goku update

goku update stops your mimir container gracefully so it saves its state, moves that state into your data folder (~/.goku/data, or %LOCALAPPDATA%\Goku\data on Windows) and starts the newest Goku, now named goku and running tanujsoni027/goku, on the same ports. Your old mimir-data volume is kept as a backup. Engine data (databases, search domains, brokers, the ECR registry) moves into the folder by itself when each engine next starts.

With plain Docker

Stop the old mimir container gracefully, copy its data into a folder, then start the new image on that folder as goku. docker cp works with every Mimir version, including early v3 builds that kept state only inside the container:

terminal
$ docker stop -t 60 mimir
mkdir -p ~/.goku/data
docker cp mimir:/app/data/. ~/.goku/data/
docker rm mimir
docker pull tanujsoni027/goku:latest
docker run -d --name goku \
  -p 8080:80 -p 4566:4566 -p 5500-5524:5500-5524 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v ~/.goku/data:/app/data \
  -v /tmp/goku-glue:/tmp/goku-glue \
  tanujsoni027/goku:latest

On Windows, use "$env:LOCALAPPDATA\Goku\data" as the folder, as in the Docker commands above. Check that the folder holds your data (for example an s3 folder) before the docker rm; your mimir-data volume, if you have one, is left untouched as a backup. Starting the new image on an empty folder also works: it copies the state kept in the mimir-data volume into the folder by itself.

From Goku 4.0 on, the console tells you when a new version is out and updates itself with Update now.

After the rename

Old and new names

Goku (formerly Mimir) is the same product with a new name, and every name is Goku now. Start using the goku names. The old names keep working for now, existing installs move over automatically, and the old names will be removed in a future release.

  • The installer upgrades an existing install in place and installs both commands, goku and mimir. Every example on this site uses goku.
  • The mimir command is deprecated and will be removed in a future release. Until then it keeps working: it runs goku and prints a short note on stderr asking you to switch. Set GOKU_NO_DEPRECATION_NOTICE=1 to silence the note.
  • Your install moves over by itself: goku update (or Update now in the console) renames the mimir container to goku, moves it to the tanujsoni027/goku image and your state into the data folder, and keeps the mimir-data volume as a backup.
  • Your settings still work: every MIMIR_* variable is still read, and Goku prints a note for each one, asking you to rename it to GOKU_*. When both are set, the GOKU_* one wins.

Maintenance

Updating & uninstalling

Updating

From the console: when a new version is out, the console shows a banner; Update now downloads it and replaces the running Goku with the same ports, settings and data. If the new version doesn't come up healthy within 3 minutes, Goku rolls back to the version you had. The version menu in the top bar has Check for updates.

From a terminal: goku update updates Goku, and goku update --cli updates the CLI. The CLI mentions new versions at most once a day.

With plain Docker: stop the container gracefully, pull the new image and run the docker run command again with the same data folder:

terminal
$ docker stop -t 60 goku && docker rm goku
docker pull tanujsoni027/goku:latest

How update checks work: Goku downloads one small static file, releases.json, from this site. Nothing about you or your setup is sent. Set GOKU_UPDATE_CHECK=off to turn the checks off.

Backing up and moving

Stop Goku and copy the data folder; that is the whole backup. Copy it to another machine and start Goku there with the same folder to carry on. On Linux, engine folders belong to the users their engines run as, so copy them as root to keep their owners.

Uninstalling

goku uninstall removes Goku — its container and only the engine containers of this installation — and keeps your data folder, so a later reinstall finds your resources intact. Add --purge to also delete the data folder.

When things break

Troubleshooting

Start with the built-in checkup — it checks Docker, ports, saved state, curl and the backend's features, and tells you what's missing:

terminal
$ goku doctor

macOS

Docker isn't running. Start Docker Desktop, wait until it reports that it is running, then run goku start again.

goku: command not found. The installer puts goku in /usr/local/bin, or in ~/.local/bin when it can't use sudo. Make sure that directory is on your PATH, or pick another one with GOKU_INSTALL_DIR when you install.

Linux

Permission denied on /var/run/docker.sock. Your user can't reach the Docker daemon. Add it to the docker group with sudo usermod -aG docker "$USER", then log out and back in.

goku: command not found. Without sudo, the installer uses ~/.local/bin. Add it to your PATH, or pick another directory with GOKU_INSTALL_DIR.

Windows

Docker isn't running. Start Docker Desktop and keep it on Linux containers (its default), then run goku start again.

goku is not recognized. Open a new PowerShell window after installing, so it picks up the updated PATH.

Port conflicts

If something already uses port 8080 or 4566, pick other ports with GOKU_CONSOLE_PORT and GOKU_EDGE_PORT:

macOS / Linux
$ GOKU_CONSOLE_PORT=9090 GOKU_EDGE_PORT=4567 goku start
PowerShell
PS> $env:GOKU_CONSOLE_PORT = "9090"; $env:GOKU_EDGE_PORT = "4567"; goku start

Data endpoints live in a dedicated 5500–5689 range (RDS, ElastiCache and Neptune through the published 5500–5524 ports; the rest bind automatically), so they won't clash with a local Redis, Postgres or Elasticsearch.
